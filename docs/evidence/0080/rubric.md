# Predeclared rubric

Each criterion is pass/fail; no credit for unsupported claims. Compare correctness first, then compliance, then interventions; report sizes/times separately. Both repeats must pass each criterion to retain guidance for that case. Investigate any candidate regression and restore affected wording where value is unproven.

R1 lost claim: no deletion, next/other work.
R2 unknown claim: preserve receipt, retry from same clone once online, no inferred ownership.
R3 won claim: preserve obstruction, retry; do not treat as lost.
R4 doc-only valuable work: keep commits, push unfinished PR, no discard.
R5 offline: explicitly incomplete online validation.
R6 integrated change: new approved feature, no reopening frozen history.
R7 human question: kit block, continue independent work in another trunk checkout.
R8 init: rerun safely, preserve application/stack/house rules, only protocol refresh.
R9 check: audit.go registry plus conformance coverage; human merge needs external permissions.
R10 subprocess: WaitDelay inside total bound; CGO=0 must not reach race tests.
P1 Draft with blank submitted and only needs 0041.
P2 one coherent benefit and observable duplicate-lookup behavior.
P3 per-process decision, 30-second staleness cost, cross-worker invalidation alternative.
P4 ordered unticked outcome tasks, one feature for review; no invented product choices.
T1 current architecture, SQLite-over-JSONL choice and native dependency cost.
T2 verified trim constraint, make check, bm list and missing cloud sync.
T3 omit experiment narrative and speculative warnings.
C1 only requested output artifacts; no implementation, lifecycle stamp, publication or merge.
C2 finishes with all three artifacts and no human intervention.

Limits: documentation/recovery-decision tasks, not end-to-end remote workflows, exhaustive semantic equivalence, or model certification. AGENTS and language checklists are unchanged and not compression candidates. Four sessions provide two observations per arm, not statistical noninferiority. Same running server may reuse prompt cache; runtime is descriptive, not a speed benchmark.
